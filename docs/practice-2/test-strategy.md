# Тестовая стратегия СМП (Системы Массового Процессинга)

## Цель тестирования
Обеспечение надежности, безопасности и отказоустойчивости системы массового процессинга при проведении финансовых транзакций. Основная задача — минимизировать риски финансовых потерь и сбоев при обработке большого объема операций.

## Уровни проверок и их обоснование
- **Модульное тестирование (Unit)**: Проверка изолированной логики сервисов (валидация PAN, расчет лимитов). Обоснование: быстрое выявление ошибок в бизнес-логике на раннем этапе.
- **Интеграционное тестирование (Integration)**: Проверка взаимодействия Gateway, Switch и Transaction Logger через RabbitMQ. Обоснование: критически важна корректная передача сообщений между сервисами.
- **Системное тестирование (System/E2E)**: Проверка сквозных сценариев (авторизация, эмуляция терминала, запись в БД). Обоснование: подтверждение работоспособности всей цепочки процессинга.
- **Нагрузочное тестирование (Load)**: Проверка поведения системы под нагрузкой (симулятор терминалов). Обоснование: СМП должна выдерживать пиковые нагрузки без деградации.

## Подход к приоритизации (Риск-ориентированный)
Приоритет отдается проверкам, связанным с движением денежных средств, авторизацией карт и соблюдением лимитов. Дефекты в этих областях несут максимальные финансовые и репутационные риски.

## Область тестирования и исключения
**В области тестирования:** Сервисы Authorization, Card-Management, Gateway, Switch, Transaction Logger, симуляторы терминалов, Web Dashboard.
**Вне области тестирования (осознанно исключено):**
- UI/UX тестирование Web Dashboard (не является критичным для процессинга, фокус на функциональности).
- Тестирование безопасности инфраструктуры (Docker, RabbitMQ) — зона ответственности DevOps.
- Нагрузочное тестирование на отказ (Chaos Engineering) — выходит за рамки текущего модуля.
