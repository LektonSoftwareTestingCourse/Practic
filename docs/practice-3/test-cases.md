# Практика 3 — тест-кейсы и пирамида тестирования



## 1. Новые тест-кейсы

Формат: ID, связанное требование, уровень пирамиды, вид, предусловие, шаги, ожидаемый результат, источник. Уровень выбран как самый низкий, который достаточно проверяет указанный риск.

| ID | Связанное требование | Уровень пирамиды | Вид | Предусловие | Шаги | Ожидаемый результат | Источник |
|---|---|---|---|---|---|---|---|
| N01 | Нормализация запроса авторизации | unit | Позитивный | Известны обязательные поля запроса | Передать корректный `AuthorizationRequest` в normalizer | Поля нормализованы детерминированно; значимые данные не теряются | Класс эквивалентности: корректный запрос; `services/switch/.../AuthorizationRequestNormalizer.java` |
| N02 | Определение BIN по PAN | unit | Граничный | PAN представлен строкой | Проверить PAN длиной 6 символов и PAN короче 6 | BIN извлекается только при длине ≥ 6; короткий PAN обрабатывается безопасно | Граничное значение; `services/switch/.../RouteService.java` |
| N03 | Комиссия эквайринга | unit | Позитивный/граничный | Известны сумма и правило комиссии | Проверить нулевую, обычную и большую сумму | Расчёт соответствует формуле; граничные суммы не дают неожиданного округления | Граничное значение; `services/merchant-acquirer/.../FeeCalculator.java` |
| N04 | Маскирование PAN в логах | unit | Безопасность | Есть полный PAN | Вызвать masker для PAN корректного формата и некорректной строки | Полный PAN не попадает в диагностический вывод; маскирование устойчиво к плохому вводу | Сценарий/безопасность; `services/merchant-acquirer/.../MaskerPan.java`, `services/authorization/.../AuthorizationLogEventListenerImpl.java` |
| N05 | Статус карты влияет на авторизацию | unit | Бизнес-правило | Карта существует в каждом из статусов | Проверить ACTIVE, INACTIVE, BLOCKED, EXPIRED | Авторизация разрешается/отклоняется в соответствии с правилами сервиса; причина отказа корректна | Классы эквивалентности/состояние; `services/authorization/.../AuthServiceImpl.java`, `services/card-management/.../models/CardStatus.java` |
| N06 | Валидация PAN на REST API | api | Негативный | Сервис Card Management запущен | `GET /api/cards/{pan}` с неверным PAN | HTTP 400 и единый формат ошибки; запрос не попадает в бизнес-логику как валидный PAN | Контракт; `services/card-management/.../controllers/CardController.java`, `docs/api-spec.md` |
| N07 | Создание карты | api | Позитивный | Сервис доступен, BIN допустим | `POST /api/cards` с валидными полями | HTTP 201; ответ содержит созданную карту и ожидаемые поля | Контракт; `services/card-management/.../controllers/CardController.java` |
| N08 | Лимит пагинации | api | Граница | Сервис доступен | Запросить список с `limit=0`, отрицательным `offset`, затем валидные значения | Невалидные значения отклоняются валидацией; валидный запрос возвращает страницу | Граничное значение/контракт; `services/card-management/.../controllers/CardController.java` |
| N09 | Неизвестный BIN | api | Негативный | BIN Lookup доступен | Запросить BIN, отсутствующий в справочнике | API возвращает документированный отказ/ошибку; Switch не пытается авторизовать неизвестного эмитента | Контракт; `services/switch/.../RouteService.java`, `services/authorization/.../client/BinLookupClient.java` |
| N10 | Репозиторий сохраняет транзакцию | integration | Позитивный | PostgreSQL поднят, схема мигрирована | Сохранить APPROVED и DECLINED через TransactionService; прочитать записи | Обе записи сохранены, статус и поля совпадают с запросом | Состояние БД; `services/transaction-logger/.../service/TransactionService.java`, миграция `V1__create_transactions_table.sql` |
| N11 | Outbox сохраняется как PENDING | integration | Позитивный | PostgreSQL доступен | Создать событие карты через сервис; прочитать `outbox_event` | Событие записано в той же БД, первоначальный статус PENDING | Состояние БД; `services/card-management/.../events/CardEventNotifierImpl.java`, `.../services/OutboxEventProcessorImpl.java`, `.../db/migration/V5.5__init_outbox_events_table.sql` |
| N12 | Outbox → RabbitMQ → Notification | integration | Асинхронная доставка | PostgreSQL и RabbitMQ доступны; consumer активен | Создать карточное событие, дождаться обработки outbox и уведомления | Outbox становится PROCESSED, сообщение попадает в `card-notifications`, Notification Service сохраняет уведомление | Сценарий/состояние БД; `services/card-management/.../services/OutboxEventProcessorImpl.java`, `services/notification-service/.../listener/CardEventListener.java` |
| N13 | Switch публикует транзакцию в очередь Logger | integration | Асинхронная доставка | RabbitMQ и Logger доступны | Отправить сообщение через `LoggerClient`, проверить consumer и БД Logger | Сообщение маршрутизировано в `transaction-log`, consumer обрабатывает его и запись появляется в БД | Контракт AMQP/состояние БД; `services/switch/.../service/LoggerClient.java`, `services/transaction-logger/.../listener/TransactionLogListener.java` |
| N14 | Publisher confirm / отказ публикации | integration | Отказоустойчивость | RabbitMQ доступен для позитивного сценария; для негативного брокер отключается | Опубликовать сообщение при рабочем брокере; повторить при недоступном RabbitMQ | Позитивный сценарий подтверждается интеграционным тестом; негативный должен обнаружить, что `LoggerClient.log()` сейчас не ожидает явно ack/nack и может вернуть `true` до подтверждения | Сценарий/контракт; `services/switch/.../service/LoggerClient.java`, `services/switch/src/main/resources/application.yml` |
| N15 | Сквозной отказ авторизации и логирование DECLINED | e2e | Сквозной негативный | Compose поднят; тестовая карта/запрос подготовлены так, чтобы авторизация была отклонена | Отправить запрос через Gateway; проверить ответ и затем запись в Logger | Клиент получает DECLINED с причиной/кодом; запись DECLINED появляется в Logger асинхронно; баланс/резерв не меняется | Сквозной сценарий; `services/switch/src/main/java/com/processing/service/RouteService.java`, `services/transaction-logger/src/main/resources/db/migration/V1__create_transactions_table.sql` |
